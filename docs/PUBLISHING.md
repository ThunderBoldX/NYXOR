# Публікація NYXOR на GitHub

[← README українською](../README_UK.md)

## Перехід на нову структуру

Для цього оновлення використовуй GitHub Desktop: потрібно зафіксувати як нові файли, так і видалення старих шляхів.

1. Встанови [GitHub Desktop](https://desktop.github.com/) і ввійди у свій акаунт.
2. Вибери **File → Clone repository → URL**, встав `https://github.com/ThunderBoldX/NYXOR` та натисни **Clone**. Зверни увагу на **Local path** — адресу локальної папки репозиторію.
3. Розпакуй підготовлений `NYXOR-GitHub-update.zip` в окрему папку, поза клонованим репозиторієм. У ньому є папка `NYXOR`, файли `Update-NYXOR.cmd`, `Apply-NyxorUpdate.ps1` та коротка інструкція.
4. Запусти `Update-NYXOR.cmd` подвійним кліком.
5. Встав **Local path** клонованого репозиторію, коли скрипт його попросить. Він перевірить контрольні суми, збереже копії замінених і старих файлів у сусідній папці `NYXOR-backup-…`, перенесе відомі застарілі файли з репозиторію та скопіює нову структуру. `.git` та локальні облікові дані залишаться на місці. Невідомі файли скрипт не прибирає.
6. Повернися в GitHub Desktop. У **Changes** мають бути нові `core/`, `tools/`, змінені документи та видалені старі файли з кореня. Переглянь список, введи повідомлення `Organize Android app and shared core`, натисни **Commit to …**, потім **Push origin**. Якщо основна гілка захищена, створи гілку для змін та Pull Request.

Скрипт змінює тільки локальну копію. Публікація відбувається після **Push origin**. Історію комітів видаляти не потрібно. Після оновлення скрипт можна запускати повторно; перед кожним запуском створюється окрема резервна копія.

Інструкції GitHub: [клонування](https://docs.github.com/en/desktop/adding-and-cloning-repositories/cloning-and-forking-repositories-from-github-desktop), [перегляд і збереження змін](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop).

## Що додати до репозиторію

README вже використовує відносні посилання. Завантаж разом із кодом:

- `README.md` (англійська) та `README_UK.md` (українська);
- всю папку `docs/`, включно з `assets/nyxor-banner.svg` і вісьмома PNG: українські у `screenshots/`, англійські у `screenshots/en/`;
- актуальні вихідні файли Android і ядра NYXOR.

Після пушу GitHub покаже банер та скріншоти автоматично. Зовнішній хостинг для зображень не потрібен. Самі PNG можна також додавати до опису релізу. Вони використовують демонстраційні дані — зберігай цю позначку в описі.

## Як опублікувати APK

1. Запуш актуальний код у `ThunderBoldX/NYXOR`.
2. Відкрий **Releases → Draft a new release**.
3. Створи тег, наприклад `v2.2.0-preview`, на коміті з цією версією.
4. Додай короткий список змін і прикріпи зібраний `.apk` у вкладення релізу. Назва файлу може бути `NYXOR-Android-2.2.0-preview.apk`.
5. Для поточної тестової збірки познач **pre-release**. Перевір вкладення та опублікуй реліз.

Кнопка **«Релізи та APK»** в README веде на загальну сторінку Releases, тож працюватиме і для preview. Архів **Source code**, який GitHub створює автоматично, не є інсталятором: APK потрібно прикріпити окремо. Пуш коду сам по собі його не публікує.

## Підпис і локальні дані

Поточний APK — preview з debug-підписом. Для публічних стабільних збірок налаштуй власний release signing і збережи ключ поза репозиторієм. Зміна ключа перешкоджає звичайному встановленню поверх уже встановленої версії; перейменування APK підпис не змінює.

`.gitignore` виключає APK, файли авторизації, локальні налаштування, журнали та ключі підпису. Перед пушем переглянь список змін; не додавай такі файли примусово. APK розміщуй у вкладеннях Releases.

Якщо поширюєш архів із `docs/CHECKSUMS.txt`, онови його після останньої зміни файлів. Новий вихідний архів, підготовлений разом із цим README, вже містить оновлені контрольні суми.
